# 11 · 模板 · 字段记录模板（字段 Schema 唯一事实源）

> 所有类目、所有字段统一用本块记录。新增条目时复制下方「标准条目块」；脚本依赖固定前缀与枚举值解析，请勿改字段名。

## 标准条目块

```
- 字段名：
- 标准答案：
- 短版：
- 长版：
- 关键词：
- 写作策略：
- 适用场景：
- 不适用/禁忌：
- 来源：
- 版本：v1
- 状态：草稿
- 最后确认时间：
- 备注：
```

## 字段说明

| 字段 | 说明 |
|---|---|
| 字段名 | 条目标识，如 GPA、自我介绍-1 分钟 |
| 标准答案 | 默认采用的完整答案，可直接复制 |
| 短版 | 受限字数（如 100 字内）或表格场景用 |
| 长版 | 不限字数或需要展开的场景用 |
| 关键词 | 便于检索与匹配岗位 JD 的词汇 |
| 写作策略 | 这段内容"怎么写"的方法论 |
| 适用场景 | 何时用短版 / 标准版 / 长版 |
| 不适用/禁忌 | 不该出现的内容与写法 |
| 来源 | 官方材料 / 证书 / 用户口述 / 公司信息页 |
| 版本 | `v1` 起步，每次内容变更 +1 |
| 状态 | 仅允许 `草稿` / `已确认` / `废弃` |
| 最后确认时间 | 格式 YYYY-MM-DD |
| 备注 | 敏感标注、待核实项、历史值等 |

## 版本与状态规则

1. 新条目：状态「草稿」、版本 v1。
2. 用户确认后：状态改「已确认」，写最后确认时间。
3. 内容变更：版本 +1，并在 `10_更新日志.md` 留痕（用 log_update.cmd）。
4. 被替代的旧版本：标「废弃」，或把历史值保留在备注。
5. 检索主答案：优先「已确认」且版本号最高；同字段出现两个「已确认」按冲突处理。

## 机器约定

- 文件编码 UTF-8；条目以行首 `- 字段名：` 开始，条目之间用仅含 `---` 的行分隔。
- 多行内容写在同一字段行内或缩进续行；不要在条目内部出现行首 `- 字段名：`。
- 日期统一 YYYY-MM-DD，时间统一 YYYY-MM-DD HH:MM。
