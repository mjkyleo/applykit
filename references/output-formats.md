# 标准输出骨架

输出前按场景取对应骨架，保证格式稳定、可复制。`【】` 为固定段落标题，不省略。

## 1. 检索回答（流程 D）

```
【检索结果】
- 类目/公司岗位：……
- 命中条目：字段名、状态、版本（多版本时列出版本选择理由）

【可直接填写】
……（标准答案原文，单独成段，便于整段复制）

短版（≤N 字场景）：……
长版（展开场景）：……

【来源文件】
02_教育经历.md（或 08_公司岗位记录/字节跳动_产品经理.md）

【版本 / 最后确认时间】
v3 / 2026-09-10（已确认）

【冲突或待确认】
无
```

要点：
- 主答案只放「已确认」最新版；用草稿时必须在版本行标注"草稿，未确认"。
- 短版/长版只在题目有字数或场景要求时给出，避免冗余。
- 敏感字段默认脱敏输出。

## 2. 新增确认（流程 B，写入前）

```
拟新增条目如下，请确认是否写入 <文件名>：
- 字段名：……
- 标准答案：……
- 短版 / 长版：……
- 关键词：……
- 状态：草稿 v1
确认写入吗？需要修改哪里？
```

用户确认后才落盘，并运行 log_update.cmd（旧值"（无）"）。

## 3. 冲突报告（流程 E）

```
发现版本冲突，已暂停更新并登记到 09_冲突与待确认.md：
- 字段：……
- 旧版本：……（来源 / 时间）
- 新版本：……（来源 / 时间）
- 影响范围：……（哪些公司岗位/网申字段会受影响）
以哪个版本为准？（A 旧版 / B 新版 / C 都不对，我重新提供）
```

裁决后：更新条目、09 移入已解决、log_update.cmd 记日志（确认人=用户）。

## 4. 更新结果（流程 C，无冲突）

```
已更新 <文件名> 的 <字段>：vN → vN+1
- 旧值：……
- 新值：……
- 状态：已确认 / 最后确认时间：YYYY-MM-DD
已记入 10_更新日志.md。
```

内容无变化时输出：`该字段与现有已确认版本一致，未做改动（幂等）。`

## 5. 体检报告（流程 F）

先运行 `scripts\scan_library.cmd <W>`，再用自然语言归纳：条目总数与状态分布、草稿数、待裁决冲突、长期未复核项、缺失/空文件，最后给"下一步建议"清单（如：先确认 N 条草稿、裁决 M 条冲突、补建缺失文件）。

## 6. 查无记录（流程 D 分支）

```
当前工作目录未记录「……」。
是否现在新增？如新增，请补充：标准答案、适用场景（以及字数/语言要求）。
```
